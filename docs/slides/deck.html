04 / 10 · How the agents work
How the agents work

Four agents, one evidence trail

01find

Leak Hunter

Six fixed SQL checks find the leaks; the fast model ranks and describes them.

Nemotron 3.5 Lightning → findings f001–f006
02explain

Explainer

Markovian reasoning on the deep model; every cause cites a finding.

Nemotron 3 Ultra · Markovian → cited explanation
03forecast

Forecaster

Deterministic cash math in code, not a model. Six-month projection and what-ifs.

TypeScript · no model → 6-month cash + what-ifs
04decide

CFO

Deep model ranks three moves; H-MEM changes the ranking from past decisions.

Nemotron 3 Ultra · H-MEM → 3 moves + memory note
Evidence + trace
6 findings · 3 moves · one line per step and model call
logs/<run_id>.jsonl
Critic loop

Reject a model answer that invents a number; retry once, then use the deterministic fallback.

[confirm P5]
Source: docs/architecture.md · backend/src/agents/ · docs/contracts.md §5 P5 · 04 / 10
The important design choice is separation. SQL finds the facts. The models rank, explain, and choose wording. Code does the cash math. If a model answer is not grounded in the evidence, the critic rejects it and the system falls back to a safe answer.

Grounding rule

A model may only cite amounts that appear in the finding or its evidence rows. If Nightshift is offline, deterministic fallbacks keep the same numbers. Full trace: logs/<run_id>.jsonl.

Trace run_20261025_133016 → leak_hunter → explainer → forecaster → cfo 6 findings · 3 moves · 1 run
Source: docs/architecture.md · metadata.json · docs/engine-tests.md P5 · 06 / 10
This is the reasoning architecture the track asks for. Nemotron does the language work, but it is bounded by evidence. Markovian gives the Explainer a step-by-step loop. H-MEM makes the next run different because Sara made a decision. The deterministic fallback is deliberate: a demo without an API key still finds the same six leaks.

What is unique

Not a chatbot over a spreadsheet

01

Federated data

Postgres + a public FX source behind one Zetaris layer.

4 views · 1 read path
02

Grounded reasoning

SQL finds facts; models rank, explain, and choose wording; code does the forecast.

every amount traced to a view row
03

Visible engines

World Model, H-MEM, and Markovian are tested integrations — not prompt labels.

10 tests per engine
04

Human in the loop

Every move waits for approval, and the decision changes the next run.

decision → memory → next run
05

Honest fallback

Without Nightshift, the same six leaks and numbers still work.

6/6 leaks without an API key
Zetaris views→evidence→grounded model output→deterministic math→human decision→memory changes next run
